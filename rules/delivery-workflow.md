# 规则包：交付工作流与恢复（delivery-workflow）

适用范围：内容就绪门、交付制作台、Guided Workflow、阶段确认、检查点恢复。

## R-DW-01 就绪门先于制作

选择交付形式后先执行内容就绪评估，用户确认 Content Baseline 后才进入正式制作；硬性缺口存在时不进入制作。[WD §7] [WF-07]

## R-DW-02 缺口引导写回文件

缺口分硬性/质量两级；引导说明缺什么、为什么需要、影响哪里、如何补充；补充结果必须写回 Workspace 文件，不能只留在聊天历史。[WD §7] [WF-07]

## R-DW-03 制作台在同一工作区

交付制作台是智能工作区内的专用模式（来源与制作目录、阶段编辑与预览、Skill 引导三栏），不启动独立应用、不失去来源上下文。[WD §8] [WD §15.2]

## R-DW-04 引导协议统一组件

Guided Workflow UI Protocol 用统一组件呈现 Skill 声明的阶段、输入 Schema、问题、候选方案、确认策略与恢复状态；客户端不把任何 Skill 的问题和阶段写死。[WD §8.1] [WF-06]

## R-DW-05 阶段 ID 唯一

四类交付物的阶段只使用 UIC §7 的稳定 stage ID；单页返工、按页可编辑重建、一致性审查、静态包导出和媒体子检查是 stage 内 action，不产生第二套阶段。[UIC §7]

## R-DW-06 确认是版本基线

确认形成版本基线而非永久锁；返回修改上游内容时先展示受影响范围，允许只更新当前交付物或全部关联交付物；关闭制作台后从持久状态恢复，不重新开始。[WD §8.6] [WF-03]

## R-DW-07 机器真相与项目目录分离

Workflow 机器真相在 App Data 本地 SQLite，不进项目目录或同步盘；项目目录只保存人类可读状态与 checkpoint manifest；复制项目跨机器打开时校验路径、哈希与版本后创建新 run binding，不自动重放未完成外部动作。[WD §12] [WF-01]

## R-DW-08 失败与重试语义

重试不得重复扣费或覆盖已验收 Artifact；远程发布成功而本地记录失败时保留可恢复 journal；failed-run 证据与 Artifact 提升走 staging/quarantine 流程。[WD §12] [WF-05]

## R-DW-09 Baseline 与来源绑定

就绪确认后生成来源清单与 Content Baseline；来源 revision 变化时重新执行影响分析，不静默使用过期内容。[WD §7] [WD §12] [WF-08]
