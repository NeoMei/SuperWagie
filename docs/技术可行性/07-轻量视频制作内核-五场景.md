# 轻量视频制作内核与五个首发场景

> 状态：产品方向与方案 B 已确认；macOS 媒体层 PoC 已执行，Electron Render Worker Host、Windows、Credits 与人工 Review 未通过  
> 确认日期：2026-08-29  
> 内部组件名：`Lightweight Video Runtime`

## 1. 已确认方向

SuperWagie 不直接集成 OpenMontage，也不把 Remotion 作为生产版必需依赖。系统独立重写一个轻量级视频制作能力，只实现 SuperWagie 真正需要的 OpenMontage 式 Agent 工作流和 Remotion 式确定性帧合成思想。

首发范围固定为五个场景，优先级顺序如下：

1. 网站 Demo 视频；
2. 教学课件视频；
3. PPT 讲解视频；
4. 图片绘本视频；
5. 照片动态视频。

五者不是五个独立 Skill UI，而是一个系统内置 `Video Delivery Workflow` 的五个制作 Profile。已确认采用单一“制作视频”入口：Agent 先根据目标、素材和当前 Content Scope 自动选择 Profile，只有无法可靠判断时才追问。界面不预先展示五张场景选择卡，也不在工作台拆成五个入口。

重写边界包括：

- 不复制 OpenMontage 的源代码、Prompt、模板、Schema 或 UI；
- 不复制或修改 Remotion 源码，不依赖 Remotion Studio、Player、Renderer 或其 npm 包；
- 可以研究公开的产品行为、通用工作流模式和帧驱动视频原理，再独立定义 SuperWagie 的 Workflow、Scene IR、渲染器和测试；
- 保留来源记录、设计记录和独立实现证据，确保 clean-room 边界可审计。

## 2. 产品位置

“视频”是继 PPT、长文档和 HTML 之后的第四类正式交付物，仍然从智能工作区进入：

```text
内容工作区
→ 制作交付物
→ 视频
→ Agent 自动识别制作场景；不明确时才询问
→ 网站 Demo / 教学课件 / PPT 讲解 / 图片绘本 / 照片动态
→ 引导、样片、完整制作、Review、导出
```

生产界面只使用 SuperWagie 的三栏工作区、Agent Composer、结构化确认卡和视频 Review。没有多轨时间线、节点编辑器、代码编辑器、Provider 配置、Backlot、Remotion Studio 或其他 Skill 自有 UI。

用户通过语义修改视频，例如：

- “鼠标点击这里时放大”；
- “第三幕改成流程图讲解”；
- “这一页绘本停留久一点”；
- “这张合照不要裁掉右边的人”；
- “保留旁白，只换画面”；
- “字幕再短一点”。

每条修改绑定稳定的 `scene_id`、`shot_id`、`asset_id`、时间范围和 Artifact revision，支持局部失效与重渲染。

## 3. 统一架构

```text
Agent + Guided Workflow
          ↓
Video Profile Director
          ↓
Treatment / Script / Storyboard / Asset Plan
          ↓
SuperWagie Scene IR + Timeline IR
          ↓
┌──────────────────────────────────────┐
│ Asset Workers                       │
│ Browser Capture / Image / TTS       │
│ Diagram / Subtitle / Music / Photo  │
└──────────────────────────────────────┘
          ↓
Deterministic Frame Renderer
HTML / SVG / Canvas at exact frame time
          ↓
FFmpeg Encode / Audio Mix / Subtitle / Mux
          ↓
Media QA → SuperWagie Review → Artifact
```

### 3.1 Rust Product Core 与 Worker

Rust Product Core 负责产品事实与策略，浏览器帧求值和媒体编码分 Worker：

- Workflow、checkpoint、lease、revision 和幂等执行；
- Scene IR、Timeline IR、Artifact ownership 和依赖图；
- Worker Supervisor、Signed Runtime/External Host 解析、取消和资源限制；
- 文件事务、素材缓存、哈希、签名和 staging；
- Credits reserve/settle、事件与 QA 回执；
- 用户授权、网络 Broker 和敏感信息清理。

### 3.2 Scene IR

Scene IR 是自有、版本化、与渲染器解耦的中间格式，不接受任意 React/JavaScript 代码：

```text
VideoProject
├── profile
├── canvas { width, height, fps, duration }
├── theme { colors, fonts, motion, caption_style }
├── tracks[]
├── scenes[]
│   ├── scene_id
│   ├── time_range
│   ├── layout
│   ├── layers[]
│   ├── camera
│   ├── transitions
│   ├── narration_ref
│   └── caption_ref
├── assets[]
├── audio_mix
└── export_profile
```

V1 只实现有限、可测试的视觉原语：文本、图片、视频、SVG、形状、遮罩、光标、聚光、标注、代码/终端卡片、浏览器框、图表、字幕、简单粒子、平移缩放、裁切、淡入淡出、滑动、擦除、页面切换和基础视差。

### 3.3 帧渲染器

渲染器使用签名、固定版本的 HTML/SVG/Canvas bundle，在独立 Electron Render Worker Host 中按绝对帧号求值并输出图像序列或帧流：

- 所有动画由 `frame / fps` 推导，不依赖实时计时器和 CSS 自播放；
- 同一 Scene IR、素材和渲染器版本应得到可比较结果；
- 字体、色彩、DPI、浏览器版本和编码参数进入 render identity；
- 每个 Job 使用 ephemeral session/cache/network policy、Resource Handle 与资源上限，不读取用户 Cookies、扩展、历史或登录态；
- app_ui、diagram_editor、artifact_preview 与 render_worker 共享 Electron/Chromium 版本身份，不共享 renderer 进程或可变状态；
- Chromium 位于只读 Signed Runtime Image，不首次使用时下载；Render Worker 不进入 Agent 核心环境，也不获得 Rust Product Core 权威。

独立 FFmpeg/Media Worker 负责最终编码、音频混合、响度、转码、字幕、封装、抽帧和基础媒体分析。后续只有在包体积、速度或一致性收益被证明时，才把部分图形原语迁移到 Rust/Skia/wgpu；V1 不以重写浏览器排版和完整视频编码器为目标。

## 4. 五个制作 Profile

### 4.1 网站 Demo 视频

输入可以是公开 URL、本地开发地址、HTML Artifact 或用户授权的浏览器页面。Agent 先确认受众、要展示的功能和操作路径，再生成 Demo Script。

主要能力：

- 固定视口的浏览器导航与录制；
- 点击、输入、滚动、等待和页面切换；
- Agent 生成的光标、点击波纹、聚光、缩放、标签和步骤标题；
- 敏感字段、通知、账号和个人数据遮挡；
- 旁白、字幕、品牌片头片尾和背景音乐；
- 页面加载失败、弹窗、布局变化和录制漂移检测。

浏览器动作使用声明式 Demo Steps 和受控 CDP/浏览器自动化 Worker，不把通用浏览器控制台暴露给用户。真实网站登录、提交、购买、发布等外部动作仍遵守行内授权。

### 4.2 教学课件视频

从 Markdown Content Baseline、PPT、文档、图表、图片和录屏生成课程视频。

主要能力：

- 教学目标、受众、时长和章节规划；
- 讲稿、分镜、屏幕文字、知识卡片和章节结构；
- Excalidraw/draw.io 图解、数据图表、代码/终端演示；
- 旁白、字幕、音乐、章节和来源说明；
- 10–15 秒代表样片确认；
- 事实、术语、时长、字幕密度和教学节奏 QA。

### 4.3 PPT 讲解视频

输入是用户已有或由 SuperPPT 生成的 PPT/PPTX。它与“教学课件视频”的区别是：PPT 页面本身就是视觉事实源，视频工作流负责讲解、节奏和视听包装，不重新设计整套课件。

主要能力：

- 使用 WPS/PowerPoint 真实渲染结果作为每页视觉底图，不自行重排文字、字体和版式；
- 读取演讲者备注、页面文字、图片、图表和 Content Baseline，生成逐页讲稿；
- 为每页确定停留时长、旁白、字幕、重点区域、光标/激光笔、局部聚焦和转场；
- 支持片头、章节页、讲师信息、背景音乐和片尾；
- 页面内容需要修改时返回 PPT Delivery Workflow，经 WPS/PowerPoint 重渲染后再进入视频，不在渲染底图上伪造正文修改；
- 原 PPT 动画只有在能可靠读取和复现时才保留，否则明确使用 SuperWagie 的受控翻页和聚焦动画，不冒充原始动画；
- 对页面顺序、空白页、字体替换、裁切、旁白时长、字幕遮挡和画面清晰度执行 QA。

PPT 讲解 Profile 的必经确认点是逐页讲稿与节奏、代表页面样片和最终 Review。它可以把现有 PPT 快速转为课程视频、汇报讲解视频或异步演示视频。

### 4.4 图片绘本视频

输入可以是现有绘本图片，也可以从故事文本生成逐页图片。重点是叙事、角色与风格连续性，而不是复杂角色骨骼动画。

主要能力：

- 故事大纲、角色卡、场景卡、逐页文案和旁白；
- 角色、服装、道具、色彩和画幅一致性检查；
- 页面切换、局部平移缩放、前中后景轻视差和对话气泡；
- 旁白、角色对白、音效、音乐和字幕；
- 逐页 Review 和单页重做，不重生成已确认页面。

V1 不承诺从单张图片自动生成高质量全身角色表演；需要真实复杂动作时，进入托管视频生成能力并单独估算 Credits。

### 4.5 照片动态视频

输入为用户选中的照片、相册、文字和可选音乐。目标是高质量动态相册、纪念视频和故事化照片短片。

主要能力：

- 照片排序、分组、去重、清晰度和方向检查；
- 人脸与主体安全裁切，禁止无提示裁掉关键人物；
- 平移、缩放、旋转、景深分层、轻视差和转场；
- 标题、日期、地点、说明文字、旁白和音乐节奏；
- 低分辨率、重复照片、比例不一致和人脸裁切 QA；
- 不修改原始照片，所有增强和裁切保存为派生资产。

## 5. 统一八阶段工作流

1. **内容就绪**：检查目标、来源、素材和权限；
2. **制作设定**：识别 Profile，确认受众、时长、画幅、语气和输出；
3. **内容脚本**：网站动作脚本、课程讲稿、绘本故事或照片叙事顺序；
4. **分镜与素材计划**：生成 scene plan、资产清单、制作路线和 Credits 估算；
5. **代表样片**：选择最能代表风险的 10–15 秒真实样片；
6. **素材生产**：录制、生成、整理、旁白、字幕、音乐和派生资产；
7. **完整合成与 QA**：按 scene 局部渲染、合成、媒体检查和条件返工；
8. **最终 Review 与导出**：播放、时间点批注、局部修改并导出 MP4、字幕、封面和来源说明。

网站 Demo 的动作脚本、教学视频的讲稿、PPT 视频的逐页讲稿与节奏、绘本的角色与逐页分镜、照片视频的排序与关键裁切属于各自附加确认门。其他低风险步骤由 Agent 连续执行。

Credits 估算不应形成独立的大块费用页面。高成本步骤只在正常 Agent 回复中提供一行预计增量；Agent 面板 Composer 下方固定显示当前任务线程累计消耗，每轮交互完成后更新。`reserve → settle`、钱包选择和供应商计量仍属于后台语义；余额不足时在安全检查点暂停并允许充值后继续。

## 7. 轻量化边界

V1 明确不做：

- 通用非线性视频编辑器和手工多轨时间线；
- 任意 React/JavaScript 视频模板运行；
- OpenMontage 的全部 Provider、全部 pipeline 和 Backlot；
- Remotion Studio、Player、Editor Starter 或兼容其组件 ABI；
- 高级三维、骨骼角色动画、专业调色和 DAW；
- 为视频能力捆绑完整 Python/Node 私有 Runtime；
- 让用户选择底层模型、Provider、浏览器或编码器。

轻量化来自有限 Scene IR、五个 Profile、共享 Renderer 和 Agent 语义编辑，不是简单删除 UI 后保留庞大的第三方运行栈。

## 8. 许可证边界

- OpenMontage 当前 AGPLv3 源码不进入 SuperWagie 生产代码、私有 Capability 或构建依赖；
- Remotion 源码、npm 包、模板和商业组件不进入生产依赖；
- OpenMontage 与 Remotion 仅作为调研来源，所有实现需保留独立设计和 provenance；
- Chromium、FFmpeg、字体、编解码器、示例媒体和生成素材分别进入 SBOM 与许可证审查；
- 若未来取得商业许可并考虑引入 Remotion，只能作为可替换 Renderer Adapter，不能改变 Scene IR、Workflow 或用户体验的所有权边界。

该路径避免把 OpenMontage AGPLv3 和 Remotion 自动化产品授权作为 SuperWagie 发布的前置依赖，但不免除其他第三方组件和媒体资产的合规义务。
