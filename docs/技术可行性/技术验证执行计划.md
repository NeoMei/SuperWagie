## 2. 标准执行器和证据格式

Milestone A 首先建立统一 runner，后续所有验证使用同一命令形式：

```bash
./scripts/poc/run-gate.sh <gate-id> --platform <platform-id> --fixture <fixture-id>
```

约束：

- `gate-id`: `contract-foundation`, `gate-0` 至 `gate-6`；
- `platform-id`: `macos-15-arm64` 或 `windows-11-x64`，不用模糊的 `local`；
- 一次命令只运行一个可复现 fixture；
- 成功退出 `0`，验收失败退出 `1`，环境不满足退出 `2`；退出 `2` 不得记为通过；
- runner 自动发现仓库根，不读取或覆盖用户 `HOME`、`CODEX_HOME` 和其他 Agent 配置。

每次运行创建：

```text
evidence/<gate-id>/<run-id>/
├── manifest.json        # gate、fixture、commit/hash、platform、operator、start/end
├── environment.json     # OS、arch、app/runtime/WPS/browser/ffmpeg/font 身份
├── command.txt          # 无 Secret 的精确命令
├── stdout.log
├── stderr.log
├── results.json         # 指标、阈值、pass/fail/blocked
├── artifacts/           # 可分发的受控输出
├── screenshots/         # 必要的真实 UI/应用证据
└── decision.md          # GO / CONDITIONAL_GO / NO_GO 及 fallback
```

Secret、API Key、原始个人文档、未脱敏对话和企业账单不得进入 evidence。人工验收必须记录执行人角色、目标应用精确版本、操作步骤、保存/放弃/重开结果，不只放截图。

## 7. 决策和矩阵更新

每个 fixture 运行结束后，所有者角必须在 `decision.md` 选择：

- `GO`: 证据足以将对应要求升为 `PROVEN_POC` 或在其他门满足时进入生产切片；
- `CONDITIONAL_GO`: 路径可行，但必须记录具体限制、平台差异和 fallback；
- `NO_GO`: 达不到产品/安全/许可证阈值，停止相关生产实现并回到产品决策；
- `BLOCKED_ENVIRONMENT`: 环境不具备，保持原技术状态，不把未运行记为失败或通过。

只有同时满足以下条件才更新技术矩阵：精确命令退出成功、`results.json` 满足阈值、原始证据完整、决策签署、fallback 与平台差异已记录。“已经有代码”、“另一个项目跑过”或“单元测试通过”不单独触发升级。

`GO` 签署必须在对应 run 的 `decision.md` 中同时绑定 `gate`、`fixture`、规范化 `platform` 和该 run 的 `results.json` 原始字节 SHA-256，并记录 `owner role` 与 UTC `signed_at`。需要 macOS/Windows 的 fixture 必须分别存在本平台的绑定签署；复制另一平台或另一 run 的决定文本、只写“已确认”、或仅有统一入口生成的 draft 都不能计入 `signed_go`。

## 8. 从 Gate 到生产垂直切片

Gate 证据通过后，Production Implementation Plan 按下列最小切片编写，每片必须从真实 UI 入口走到真实 Artifact/服务回执：

1. 新建 Project → 编辑 Markdown → 外部 Obsidian 重开；
2. 手动/Agent/Project Milestone → Tasks/工作台/项目统一投影 → 外部 Obsidian 修改 → 稳定任务回写；
3. Agent Task Thread → Working Set 修改 → stop/restart → Workspace Revision；
4. Content Baseline → SuperPPT/SuperWriter/HTML → 真实 Review/官方发布；
5. 制作视频 → 代表样片 → 局部修改 → 最终 MP4/字幕/封面；
6. 设置内安装用户 Skill → 调用公开能力 → 拒绝越权 → 更新/回滚/移除；
7. 个人/企业充值 → 长任务 reserve/settle → 客户端 Session Credits 和官网账本一致。
