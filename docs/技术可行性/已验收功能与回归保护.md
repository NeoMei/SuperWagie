# 已验收功能与回归保护

## 保护对象与边界

本机制落实 R-QS-11：把已认可行为变成持续执行的测试契约，而不是依赖下一次编码时的记忆。

权威清单为 `scripts/regression/accepted-features.json`。当前登记：

| 稳定 ID | 验收依据 | 必跑检查 |
| --- | --- | --- |
| MD-LIVE-PREVIEW | 用户对 `4d4c62a` 本机实现确认：“可以这样已经很好了” | 17 项真实 Electron 界面检查：光标局部源码、非活动区域预览、定位、选区、撤销、源码保真等 |
| MD-DURABLE-LIFECYCLE | 同一代码基线已自动化验证的依赖能力，不冒充独立人工签收 | 12 项真实 Electron + Rust 生命周期检查：保存、重开、外部修改、冲突、崩溃恢复和撤权等 |

这不代表全部 Obsidian 兼容或整个产品验收。完整表格单元格编辑、数学与附件能力、原生中文输入法、真实 Obsidian 差分、Windows 与其他发布平台仍需各自证据。截图是可复核产物，当前未建立自动像素差分基线。所有回归报告的 `admission_effect` 为 `none`，不改变发布准入状态。

## 单一入口

在仓库根目录执行：

```sh
node scripts/regression/run.mjs
```

当前要求真实 macOS arm64 桌面、Node 24.18.0、Rust 1.97.1 与 Clippy；桌面依赖先按锁文件安装：`npm ci --prefix apps/desktop`。其他环境明确失败，不允许以跳过 UI 测试代替通过。

每次依次执行：回归门自身反例测试、规格锚点检查、Rust 完整测试（至少 40 项）、Clippy、Core 构建、桌面单元测试（至少 14 项）、12 项生命周期 UI、17 项 Live Preview UI。两个 UI 套件会实际构建并启动桌面应用，不依赖可选 UI 测试开关。

报告和日志、截图写入独立目录 `apps/desktop/test-results/regression/<run-id>/`。门禁不仅检查进程退出码，还检查：

- 必需检查逐项严格等于 `true`；缺项、任何额外失败、旧运行凭据和错误范围均失败。
- 单元测试不得零测试、跳过、忽略、筛选或未达到最低数量。
- 运行前后源码指纹与 HEAD 一致，避免边改边测后把旧证据算在新代码上。
- 与基线相比不得删除既有 feature、减少其必需检查、换掉绑定套件或删除受保护路径；允许新增覆盖。

本地基线为 HEAD；PR/merge queue 使用目标分支基线，main push 使用推送前基线（首次创建分支除外）。数量下限不是测试充分性的证明，必须保留行为断言，并随新功能扩展清单。

## 当前 worktree 的提交前门

版本化钩子为 `.githooks/pre-commit`，执行同一入口的 `--staged` 模式。它要求工作区与暂存区一致，且没有未纳入的非忽略文件；测试前后还检查暂存区树不变。因此通过的代码才是即将提交的代码。

遇到部分暂存或其他未提交工作时，门会停下并说明原因，不会自动 stash、覆盖或删除任何文件。应先协调这些改动，或在独立 worktree 提交；不要为了过门丢弃用户工作。

本次只给当前 worktree 设置 `core.hooksPath`，不修改全局或其他 worktree 的钩子。新 clone/worktree 不会自动继承本机配置。安装前先检查现有钩子并确认 `extensions.worktreeConfig=true`；满足条件后，在该 worktree 根目录运行：

```sh
chmod +x .githooks/pre-commit
git config --worktree core.hooksPath "$PWD/.githooks"
git config --show-origin --get core.hooksPath
```

若已有钩子，应合并调用链，不直接覆盖。若未启用独立 worktree 配置，不要擅自改公共配置。本地 Git 钩子可被仓库所有者绕过，因此它是开发流程约束，不是不可绕过的安全边界；agent 不得绕过它来宣称完成。

## CI 与受保护文件审查

`.github/workflows/accepted-feature-regression.yml` 对所有 PR、main push 和 merge queue 执行完整检查，不使用路径过滤；固定检查名为 `accepted-features-macos`，使用 `macos-26` arm64 runner，并保留失败日志。runner 平台以 [GitHub 官方列表](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) 为准。

清单中的受保护路径及 `.github/CODEOWNERS` 覆盖测试、fixture、门禁、CI、规格与规则。修改这些文件会在报告中单独列出，必须审查是否删断言、加跳过、放宽阈值或修改测试来迎合回归。有意改变用户已认可的行为，先取得明确确认，再修订契约；修复测试本身也要给出原因与新旧证据。

保护文件列表是审查提示，不是自动审批。CODEOWNERS 只有结合必需代码所有者审查规则才能强制执行，不能把配置文件存在当作远端已受保护。详见 [GitHub 分支保护说明](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)。

2026-09-05 只读检查：当前私有仓库的 main 分支保护接口返回 403，提示需升级套餐或改为公开仓库才能启用；本次没有升级、改公开、修改远端设置或推送。因此工作流目前只在本地准备好，尚无远端 CI 运行证据，更没有“失败禁止合并”的远端保证。

后续在用户授权推送、且仓库具备相应能力后，才可启用必需状态检查 `accepted-features-macos`、代码所有者审查、过期批准失效，并限制直接推送及绕过。无需为此将私有代码公开。

## 后续编码规则

1. 改功能前读取区域规格及已验收清单；新行为补测试，故障先补能复现的回归用例。
2. 完成后跑统一入口，提交前由钩子再次验证最终暂存对象。
3. 测试/契约/阈值修改单列理由，不以删除或跳过失败测试换取绿色结果。
4. 新增已验收能力进入登记表，绑定稳定行为断言；未覆盖的行为明确标注，不宣称全部 feature 已受保护。
5. CI 与本地结果分别报告；测试能降低回归概率并阻挡已覆盖的退化，不能证明未来绝不出错。
