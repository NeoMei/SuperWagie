# SuperWagie 2.7.40-intel validation

The frozen application source is `5c1c795cfc3aec235cb3640f1037027e456c3f54`. This optional local release targets Intel Macs on macOS 12 Monterey or later. Electron is pinned to 43.8.4 with Node 24.22.1 and ABI 148. The normal main branch retains version 2.7.39 and its standard Electron dependency.

## Local behavior

SuperWagie runs its OpenCode service, projects, knowledge library, customized memory engine, terminal and speech modules on this Mac. Model calls use user-configured services. Bun, Node and OpenCode do not require separate installation. The OpenCode 2.1.4 service bundle uses the application's Node runtime and the HTTP API consumed by SuperWagie. It omits the standalone OpenCode TUI and service-management CLI. Managed engine selection retains this compatibility bundle instead of replacing it with an official Bun binary that requires a newer macOS.

The package includes crash-lock recovery, remembered usernames and the SuperWagie memory-engine label. Passwords still require entry. Seven verified Jieba dictionary and licence resources travel beside the knowledge backend, which receives the adjacent directory through `JIEBA_DICT_DIR`. Runtime startup fails explicitly if this staged directory is incomplete. It no longer depends on the build host's Go module cache.

This release replaces the website's previous 2.7.39-intel remote-client selection. Existing remote settings remain valid; users who saved a remote instance select the local instance to work on this Mac. Intel updates require manual downloads. The regular Apple silicon Mac and Windows x64 release and automatic-update feeds remain at 2.7.39. Windows ARM64 remains at 2.7.34.
