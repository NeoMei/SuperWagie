# SuperWagie 2.7.39 validation

Executable source: `a2a165de572d3daaba877fcd88ae1ceb909dc536`.
Default targets: macOS ARM64 and Windows x64. Optional architecture builds remain unchanged.

This release recovers a crashed model-journal writer without discarding billing state, keeps unrelated model providers available when the platform store cannot start, remembers the last successful username per runtime, and uses the SuperWagie memory engine name in product text. Password persistence was not added. Internal adapter identities and open-source attribution remain intact.

## Source checks

`bun run check:changed` passed before the source commit, including type-check, lint, dead-code and anti-slop checks. Focused web validation passed 232 tests across 28 files. Separate UI runs passed 40 account-page, 14 account-gate, 17 memory-panel and one memory-locale tests. Release workflow, manifest, customization and website checks also passed. Independent reviews found no blocking source or integration issues.

Writer tests exercise actual child-process termination, concurrent ownership, malformed/live owners, corrupt state preservation and shutdown ordering. Runtime regressions verify that an unavailable platform store does not prevent startup or BYOK use, while platform operations fail explicitly.

## macOS execution

The packaged app used isolated profiles with managed OpenCode disabled and an explicit isolated loopback port. A valid legacy owner with a verified dead PID was recovered. After SIGKILL, the same profile restarted and a new main process owned the store. The UNKNOWN journal remained byte-identical and the SQLite guard inode was unchanged. Graceful shutdown removed the current owner's legacy record.

Packaged first start, packaged restart and HMR each returned HTTP 200 for health and UI routes, mounted React and displayed the account gate in unsupported mode. All 24 owned processes stopped; isolated profiles and temporary state were removed. The user's installed app and data were untouched.

## Limits

No real account login, live model generation, gateway settlement, clean-machine GUI installation or updater installation was exercised in this release. The isolated macOS startup checks displayed the account gate in unsupported mode because managed OpenCode was disabled. macOS uses ad-hoc signing without notarization; the Windows installer is unsigned. Hash and source checks do not establish trusted-publisher validation.
