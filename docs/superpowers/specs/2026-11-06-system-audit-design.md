The maintainer requests repeated task reconciliation, code review and frontend/backend/UI testing, with every actionable defect repaired and reviewed before delivery.

The starting point is the completed November 5 upstream adaptation on SuperWagie 2.7.59. Its exact source and evidence are preserved in `.superpowers/sdd/2026-11-05-upstream-followup/completion-state.json` and the accompanying report. ## Scope and constraints

- Reconcile every original adaptation requirement against current source and available runtime evidence. Classify unfinished implementation separately from unavailable platform or external-service acceptance.
- Review application-owned frontend, server, native/VS Code boundaries, bundled-runtime integration and adjacent callers. Trace every reported defect from a reachable entrypoint. Vendor payloads require exact provenance and integration review; generated bytes are not manually reviewed line by line.
- Test existing package suites serially, then exercise actual frontend/backend/UI interactions in isolated profiles and temporary workspaces. Cover normal operation, errors, retries, cancellation, stale responses and cleanup.
- Repair reproducible defects, including useful low-risk fixes previously deferred. Preserve deliberate product behavior. New product features or architecture are outside this bug-fix request.
- Keep Omni Viewer, resolved-theme behavior, Hy/source retrieval, UniHub, Benma hints, updater feedback and existing customizations. Keep app 2.7.59, OpenCode 2.2.5 and Electron 44.9.3. No LibreOffice integration, unrelated dependency upgrade, release, commit, push or deployment.
- Use one product-source writer and one heavy/live execution slot. Read-only review may run in parallel. Preserve existing work and every failed-run receipt.
- Do not alter real user accounts, profiles, providers, installed global skills or paid workflows. Use explicit isolated fixtures. Real services and unsupported hosts are separate acceptance boundaries.
- User-requested repetition continues when a new actionable finding appears. Completion requires all accepted findings closed, a clean independent code pass, a second clean task/evidence reconciliation, and passing relevant regressions on final bytes. Report remaining unexecuted platform/external scenarios explicitly; do not claim mathematical absence of bugs.

## Evidence

Each finding records its ID, trigger, owning path, expected/actual behavior, reproduction, severity, fix scope, regression result and independent review outcome. Each test run records its command, exit, final source identity, result counts, errors and cleanup. The final report maps the maintainer's three requests to these receipts.
