# LLMRouter 一键模型配置与联通测试设计

状态：已确认并实现；当前文档保留为行为与边界说明。

## 目标

用户在 SuperWagie 中完成一次 LLMRouter/UniHub 授权后，能够预览并一键配置当前账户实际有权限使用的模型，将它们绑定到 Agent、辅助模型、Embedding、Rerank、视觉、OCR、语音、图片和视频等用途，并在同一页面看到每项的联通状态、失败原因和修复入口。

正常使用优先走已登录的 UniHub 托管会话；需要跨设备、无浏览器或固定 API 凭据时，支持导入或生成一个绑定到 SuperWagie 的 LLMRouter API Key。两种方式共享同一套模型目录、用途绑定、测试和回滚机制。

## 现状边界

- `ModelConfiguration` 已有连接、用途绑定、修订号和逐项测试接口。
- `unihub` 目录项当前是 `managed-media`，依赖 UniHub 登录会话，不能填写供应商 Key。
- `platform-model` 已能向模型选择器提供托管聊天模型，但默认模型来自运行时配置，不会自动写入所有用途绑定。
- 通用模型测试只覆盖部分协议，不能批量测试全部用途；同步语音、转写和图片生成还受运行时恢复边界限制。
- UniHub API Key 是一次性展示的、带账户、产品、实例和模型范围的长期凭据；SuperWagie 不能接受其他产品或其他实例的 Key 来绕过产品计费归属。

## 推荐方案

采用“托管会话优先，SuperWagie 专用 API Key 作为可选凭据”的统一向导。

方案取舍：

- **仅使用 UniHub 会话**：安全边界最简单，但无法满足无浏览器、跨设备和固定 Key 的使用场景。
- **只导入 LLMRouter Key**：实现路径较短，但容易误用 `llmrouter` 产品归属的 Key，也不能覆盖登录态下的账户切换。
- **会话优先 + SuperWagie 专用 Key**：同时覆盖桌面登录和固定凭据场景，能够在 UniHub 端强制产品、实例、账户和模型范围；这是推荐方案。

1. 用户打开“设置 → 模型配置 → 快速设置”。
2. 向导自动读取当前 UniHub 会话；会话有效时优先显示“使用当前 UniHub 账户”。
3. 用户也可以选择“导入 LLMRouter Key”或“从当前 UniHub 账户生成 SuperWagie Key”。
4. 服务端读取模型目录和权限，生成配置预览，不立即覆盖现有绑定。
5. 用户选择“仅填充缺失项”或“替换当前由此配置管理的项”，确认后原子应用。
6. 向导自动执行低成本联通测试，并在同一页面汇总成功、失败、未测试、不可用和需人工确认的项目。

不推荐把普通 `llmrouter` 产品 Key 直接当作 SuperWagie Key 使用。应用必须检查 `origin_product_id=superwagie`、正确的实例和当前账户范围；不匹配时给出生成 SuperWagie 专用 Key 的入口。

## 用户界面

### 快速设置入口

在模型配置页顶部增加“快速设置 LLMRouter”按钮。向导分为四步：

1. **授权来源**：当前 UniHub 会话、导入 Key、生成 SuperWagie Key。
2. **发现模型**：显示账户、实例、Key 到期时间、可用模型数、可用额度和模型用途能力。
3. **配置预览**：按用途显示推荐模型、现有模型、将要新增或替换的绑定，以及未满足的用途。
4. **测试与完成**：显示进度和结果，允许重试失败项、跳过高成本测试或撤销本次应用。

### 预览策略

默认选择“仅填充缺失项”，保护现有 BYOK、项目覆盖、Agent 覆盖和会话固定模型。用户必须主动选择“替换由快速设置管理的项”才能替换已有托管绑定。不得提供无确认的“替换全部”按钮。

每个用途显示：

- 当前绑定和推荐绑定；
- 模型是否在 Key 的 allowlist 中；
- 是否需要额外参数，例如 embedding dimension、TTS voice；
- 是否会产生额度消耗；
- 最终状态和修复动作。

### 状态

统一使用以下状态，不能把“已保存”显示成“可用”：

- `discovered`：目录已发现，尚未应用；
- `configured`：绑定已保存，尚未测试；
- `verified`：用途级真实测试通过；
- `failed`：测试失败，附结构化原因；
- `unavailable`：Key、账户、模型或运行时不支持；
- `skipped`：用户跳过，尤其是可能产生较高费用的媒体测试；
- `stale`：凭据或模型目录变化，需要重新发现。

## 模型发现与自动映射

新增 UniHub 的受控模型目录读取能力。对 API Key 使用 `GET /v1/models`，对托管会话使用同等权限的服务端目录读取；返回值只包含公开模型元数据，不返回 Key。

每个模型至少包含：`id`、显示名、支持的 operation、输入输出模态、上下文限制、区域、计费资产、是否允许探测和推荐级别。SuperWagie 本地目录保留用途标签和消费端要求，服务端只把同时满足“账户权限、产品实例、模型能力、当前运行时适配器”的模型作为候选。

默认映射规则：

- Agent：选择最高推荐等级的文本/工具模型；
- 辅助模型：优先选择低成本、支持文本的模型；
- Vision：只选择明确声明视觉输入的模型；
- Embedding：选择 embedding 模型并使用目录声明的维度；
- Rerank：只选择支持 rerank operation 的模型；
- OCR、STT、TTS、图片和视频：只有对应 operation 和本地消费端都可用时才绑定；
- 没有合格候选时显示 `unavailable`，不能把聊天模型伪装成 OCR、Embedding 或媒体模型。

用户可以在预览页逐用途改选模型，但不能选择 Key allowlist 之外的模型。

## 服务端接口

新增独立的 `model-configuration/bootstrap` 模块，不把向导流程堆进现有 `runtime.js`。

### 发现

`POST /api/model-configuration/bootstrap/discover`

请求只在已认证的本地运行时内处理：

```json
{
  "source": "session" | "imported-key",
  "key": "一次性提交的凭据，仅允许出现在请求体"
}
```

服务端立即验证 Key，调用 UniHub 模型目录，生成短期 `discoveryId`。响应包含账户、实例、Key 指纹、到期时间、模型目录和用途候选，不包含原始 Key。原始 Key 只进入加密秘密存储，不进入配置 JSON、浏览器状态、URL、日志或错误消息。

### 生成 SuperWagie Key

`POST /api/model-configuration/bootstrap/issue-key`

使用当前 UniHub 会话，在 UniHub 端创建 `origin_product_id=superwagie`、当前实例、选定模型范围和可选额度上限的 API Key。Key 只返回一次并直接写入本地加密秘密存储；界面只显示末四位和指纹。

### 预览

`POST /api/model-configuration/bootstrap/preview`

请求包含 `discoveryId`、当前 `revision`、应用策略和可选用途选择。响应包含完整变更计划：新增连接、用途绑定、保留项、替换项、未满足项、测试成本和风险。预览不写配置。

### 原子应用

`POST /api/model-configuration/bootstrap/apply`

服务端在现有模型配置写锁和修订号校验下，一次性写入连接与绑定，并保存一份可回滚快照。重复提交使用 `operationId` 幂等。任何用途校验失败都回滚整次应用，不能留下半套配置。

### 批量测试

`POST /api/model-configuration/bootstrap/test`

请求包含应用后的 `revision` 和用途列表。服务端按最多两个并发任务执行小型探测，返回 `testRunId`。通过 `GET /api/model-configuration/bootstrap/test/:id` 轮询状态；不让浏览器直接调用供应商。

测试默认分为两层：

- 免费或近似免费的目录/权限测试：Key 有效、模型可见、实例和 operation 匹配；
- 明确标注可能扣额度的真实测试：短文本聊天、单条 embedding、最小 rerank、短 TTS/STT。图片、OCR、视频默认只做能力检查，真实样例由用户主动点击。

### 回滚与删除

`POST /api/model-configuration/bootstrap/rollback` 使用快照和期望修订号恢复上一次应用；如果用户已经修改了其他设置则拒绝覆盖并要求重新预览。删除本地凭据只删除本地加密引用，不自动撤销远端 Key；远端撤销必须在 UniHub 账户页单独确认。

## 安全与计费

- Key 输入只经过已认证的 SuperWagie 服务端；不进 `localStorage`、URL、遥测、崩溃日志、测试快照或渲染器持久状态。
- 本地使用现有加密会话/秘密存储机制，文件权限保持 `0600`；托管服务使用服务端密钥加密，数据库只保存指纹和密文。
- 每次调用都继续由 UniHub/LLMRouter 根据 Key 的账户、产品、实例、模型 allowlist 和额度做最终授权；SuperWagie 的预览不能授权一次调用。
- Key 的产品和实例不匹配时拒绝导入；不能通过改变 Base URL 或 Model ID 绕过范围校验。
- 批量测试使用唯一幂等键、严格超时、最多一次真实探测，不自动重试可能已经产生费用的请求。
- 错误只显示分类和请求编号，不显示上游响应中的凭据、完整请求或响应正文。

## 兼容性

- Agent 和辅助模型仍由 OpenCode 的原生模型选择拥有；快速设置只通过现有默认模型入口设置推荐值，不复制出第二套 Agent 配置。
- 现有 BYOK 连接和项目/会话级覆盖保持不变。
- 当前 `managed-media` 的同步语音、转写和图片生成限制继续显示为不可用，不因“一键设置”被伪装成已验证。
- VS Code、未启动 UniHub 服务的运行时显示明确的“不支持快速设置”，不返回空成功。
- 旧版本配置文件可以继续读取；新字段使用版本化 schema 和迁移，不删除原有连接。

## 验证

后端：

- Key 目录发现、产品/实例范围拒绝、过期/撤销 Key、空目录和重复提交；
- 自动映射覆盖每种用途，禁止能力错配；
- 原子应用、并发修订冲突、回滚冲突和幂等；
- 目录测试、聊天、embedding、rerank、媒体跳过和额度不足；
- 日志、响应和配置文件不含原始 Key。

前端：

- 会话、导入 Key、生成 Key 三种入口；
- 预览只填充缺失项；
- 测试进度、失败重试、费用提示、不可用原因和回滚；
- 现有连接、项目覆盖和 Agent 默认值不被误删；
- 中英文文案、键盘操作和窄窗口布局。

端到端验收使用 UniHub sandbox 账户和合成供应商，验证“发现 → 预览 → 原子应用 → 批量测试 → 回滚”。真实余额、真实支付和高成本图片/视频测试必须作为单独验收门，不放进默认一键流程。

## 分阶段交付

1. **第一阶段**：托管会话快速设置、模型目录、预览、仅填充缺失项、聊天/Embedding/Rerank 低成本测试。
2. **第二阶段**：生成和导入 SuperWagie 专用 API Key、加密存储、回滚和 Key 状态检查。
3. **第三阶段**：接入已完成消费端的 OCR、TTS、STT、图片和视频能力；高成本测试全部改为用户主动触发。

推荐先实现第一、第二阶段，再开放媒体用途。这样可以解决“一键设置和联通测试”的核心体验，同时不会把供应商 Key、产品计费归属和当前未完成的媒体恢复边界混在一起。
