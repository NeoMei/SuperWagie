## 1. 目的与权威边界

本文定义 SuperWagie V1 Connector Plane 的产品语义：连接范围、授权与凭证、项目连接绑定、AgentWiki 知识库同步、项目记忆共享（跨设备与团队）以及失败、离线与生命周期行为。它是这些产品语义的唯一权威规格；技术调查可以补充同步协议、增量算法和传输实现，但不得改写本文确认的用户边界。

本文不解除任何技术 Gate。`docs/技术可行性/技术要求矩阵.md` 中 CON-01、CON-02、CON-03 的 `RESEARCH_REQUIRED` 状态不因本文确认而升级。

## 2. 已确认的产品原则

1. V1 只有官方 AgentWiki Connector；Connector 契约（binding、sync journal、审计）按可扩展设计，但不开放第三方 Connector 接入，第三方服务需求由用户 MCP 扩展承接。
2. 连接管理在设置内完成；项目通过连接绑定选择 Space 与本地目录；工作面板不做连接管理。
3. 授权使用系统浏览器 + Deep Link 回跳，凭证只进 OS 安全存储（Secret Vault）；自托管实例填写实例地址后走同一授权流；凭证在客户端界面永不可见。
4. 知识同步内容是真实 Markdown 文件，落在项目 Workspace 专用同步目录，全量参与本地编辑、链接、搜索和 Agent 加工。
5. Pull 与 Push 均手动发起，先预览变更清单再确认执行；无后台静默知识同步，无保存即推；同步状态常驻可见。
6. 冲突分级处理：无重叠改动由 diff3 自动安全合并并标注；重叠冲突提供采用本地、采用远程（败方自动存副本）或双栏手动合并；冲突文件挂起不阻塞同批其他文件；解决前本地内容绝不覆盖。
7. 任何解绑、断连、凭证失效场景都不自动删除工作区文件；文件降级为不再同步的普通本地内容。
8. 项目绑定 Space 后，Agent 自动获得该 Space 的只读实时查询桥；一切写入只走 Connector 同步路径；本地文件授权、Push 预览确认和 AgentWiki 服务端 ChangeSet 审核三个边界独立保留。
9. 项目记忆共享只同步人可读的项目记忆层：连续性产物自动同步个人私有区；向团队共享记忆空间写入走 Push 预览确认；Safe Memory 本体库、User Profile、未显式共享的记忆条目和敏感类别内容永不上传。

## 3. 连接与授权

### 3.1 连接范围

V1 内置且仅有官方 `AgentWikiConnector`。Connector Plane 与 User Extension Plane 分离：Connector 面向拥有独立身份、远程状态和同步要求的一方服务；用户想把其他服务接入 Agent 对话，走设置内的 MCP 扩展路径，不经 Connector 契约。

### 3.2 两层管理模型

- **实例级（设置 → 连接）**：添加、授权、撤销 AgentWiki 实例（官方 SaaS 或自托管）；查看实例下已授权 Space 与角色；管理凭证与删除连接。
- **项目级（项目连接绑定）**：在项目内选择一个已授权 Space 并确认 Workspace 内目标目录。一个连接可被多个项目绑定；一个项目同时只绑定一个 Space。解绑项目不影响连接本身。

### 3.3 授权与凭证

客户端跳转系统浏览器打开 AgentWiki 授权页，用户登录并勾选授权的 Space 与角色，授权码经 Deep Link 回客户端换取 token，凭证只存 Secret Vault。自托管实例先填实例地址再走同一流程。凭证过期、撤销和按设备管理沿用与官网登录相同的机制。

## 4. 知识库同步

### 4.1 落点与形态

Pull 的页面以真实 Markdown 落在项目 Workspace 内的专用同步目录（默认 `AgentWiki/<Space 名>/`，保持远程层级，实际路径在项目绑定时确认）。这些文件与自建内容同等参与 Obsidian 式编辑、WikiLink、标签、搜索和 Agent 加工；本地改动经 Push 预览确认后回写远程。

### 4.2 触发与预览

Pull 和 Push 都由用户显式发起，先展示变更清单（新增、修改、冲突、删除）再确认执行。项目内常驻同步状态：上次同步时间、远程是否有新变更（stale 标记）、进行中与失败状态。Agent 可以在对话中建议同步，执行同样走预览确认。没有后台静默同步，也没有保存即推。

### 4.3 冲突处理

- 同一文件无重叠改动：diff3 自动安全合并，预览清单中标注“已自动合并”。
- 同一文件有重叠改动：该文件进入冲突解决，三选一——采用本地版本（远程版自动存副本备查）、采用远程版本（本地版自动存副本备查）、双栏对照手动合并（可对照基线版本）。
- 冲突文件挂起等待处理，不阻塞同批次其他文件的同步；解决之前本地内容一个字都不会被覆盖。

### 4.4 写入边界

本地文件授权、Push 预览确认和 AgentWiki 服务器端 ChangeSet 审核是三个独立边界，任何一次同步都不能用一次笼统确认互相替代。

## 5. 项目记忆共享

### 5.1 角色定位

AgentWiki 集成承担双重角色：知识库同步（第 4 章）与项目记忆共享。项目记忆共享解决两个场景：同一用户在不同机器间恢复项目上下文；团队项目工作的共享记忆空间同步。它同步的是人可读的项目记忆层，不是记忆本体数据库。

### 5.2 个人私有区（跨设备）

任务线程收尾的异步更新完成后，`项目回顾.md` 与 `项目历史.md` 自动同步到用户在该 Space 的个人私有区（仅本人可见，备份语义）。新设备绑定同一 Space 后可一键拉取，恢复项目上下文。私有区同步只含连续性产物，无需逐次确认。

### 5.3 团队共享记忆空间

项目可将 Space 中的共享目录指定为团队共享记忆空间。向共享区写入连续性产物或显式勾选共享的记忆条目，走 Push 预览确认（发布语义，影响他人）；团队成员可 Pull 共享内容进入自己的项目。共享记忆条目按条目级幂等同步，不做文本合并。

### 5.4 边界与不同步内容

Safe Memory 本体库、User Profile、未显式共享的记忆条目永不上传；密码、密钥、支付、健康类内容永不进入任何同步路径。个人记忆归属不因共享改变：共享的是显式勾选的副本，撤回共享后远端副本按 AgentWiki 侧删除策略处理，本地内容不受影响。

## 6. 失败、离线与生命周期

### 6.1 离线与凭证失效

离线或凭证失效时，本地文件照常可用；同步能力冻结并在项目内明确提示原因；重新授权后原地继续，不要求重新绑定目录。

### 6.2 解绑与删除连接

项目解绑 Space 或删除连接时，已拉取文件与本地加工内容一律原地保留，降级为不再同步的普通工作区文件，保留来源标注、清除同步状态；文件内既有 WikiLink 不受影响。删除连接同时从 Secret Vault 清除该实例凭证。

### 6.3 底层同步语义

revision、snapshot、delta、内容哈希、idempotency、immutable Base、diff3、durable sync journal、失败恢复、远程审计事件、offline、stale revision 与部分成功状态，全部沿用最早期产品方案 §11.7 的既有定义。

## 7. 与其他子系统的边界

| 子系统 | 边界 |
|---|---|
| Billing | Connector 不同步任何账务数据；官方服务端零记忆原则不受 AgentWiki 同步影响 |
| Safe Memory | 记忆本体库与 Profile 永不经 Connector 上传；共享仅限显式勾选的条目副本 |
| Continuity | 连续性产物是记忆共享的同步对象；其生成节奏与回滚机制不变 |
| Extension | 第三方服务接入由 MCP 扩展承接，不经 Connector 契约 |
