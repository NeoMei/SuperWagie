# SuperWeb v1 Spec

## Problem Statement

今天用 Agent 做网页，通常是一句话直接生成一个完整页面：用户还没确认方向，代码已经写了；页面看起来“能用”，但版式、字体、配色和内容结构都像模型见过的平均值。出了问题也只能在整页上反复改，缺少像 SuperPPT 那样的阶段、样页和验收节奏。

SuperWeb 要把“做网页”变成一条可控的创作流程：先选方向，再做样页，再展开整页，最后用真实浏览器验收并交付。它要同时覆盖浏览型页面和工作型界面，但不把用户绑在某一个前端框架上。

## Solution

SuperWeb 是一个独立、可安装的 Agent Skill，配一个轻量 CLI 和状态机。它把网页创作拆成三个决定门：

1. **方向门**：读取需求，自动判断是“浏览型页面”还是“工作型界面”；给出 3 个差异明确的设计方向，并同时确认内容结构。用户选方向后，授权制作样页。
2. **样页门**：只做首屏 + 一个代表性区块（或应用外壳 + 一个代表屏幕），展示真实 token、真实文案和素材占位。用户确认后，授权展开整页。
3. **验收门**：完成整页、响应式与交互后，用本机 Chrome 在桌面、平板、手机三个宽度截图并检查；用户接受后，授权交付。

产物默认是可直接打开的静态 `index.html` + `assets/`，不要求构建步骤。需要 React 等框架时由用户明确要求，作为可选输出，不改变默认路径。

## User Stories

1. 作为一个不会写代码的用户，我想在开始生成前先看到 3 个不同的设计方向，这样我能选择自己喜欢的视觉路线，而不是等整页做完再推翻。
2. 作为一个要落地页的创业者，我想先确认首屏和一个代表区块，这样我能在投入整页制作前判断方向是否正确。
3. 作为一个做作品集的设计师，我想让 Agent 先理解我的内容和受众，而不是直接套一个通用的卡片式模板。
4. 作为一个做产品介绍页的用户，我想让页面有一个只属于这个产品的视觉概念，而不是任何 SaaS 都能套用的页面。
5. 作为一个做活动页的用户，我想让活动的时间、地点和行动按钮在首屏就说清楚，而不是藏在滚动之后。
6. 作为一个做后台界面的用户，我想让 SuperWeb 识别这是工作型界面，并使用安静的面板、清晰的表格和对齐的数字，而不是营销页的排版。
7. 作为一个做仪表盘的用户，我想让图表和数据有真实含义，不接受编造的统计数字和假 logo。
8. 作为一个没有品牌素材的用户，我想看到诚实的占位符和素材需求说明，而不是被塞进 CSS 画出来的假产品图。
9. 作为一个提供了 logo、产品图或截图的用户，我想让这些真实素材被优先使用，并记录在项目里。
10. 作为一个用户，我想让样页使用最终会用的字体、颜色和间距，而不是样页一套、整页另一套。
11. 作为一个用户，我想让整页的每个区块都延续已经确认的方向，而不是首屏精致、后面变成模板。
12. 作为一个用户，我想在页面上看到完整内容：完整菜单、完整价格、完整人员介绍，而不是一屏占位文字。
13. 作为一个用户，我想让页面在桌面、平板和手机上都能读，不出现横向滚动、文字溢出或按钮点不到。
14. 作为一个用户，我想在验收阶段看到真实浏览器截图和明确的问题清单，而不是只被告知“已完成”。
15. 作为一个用户，我想在验收后只针对有问题的区块返工，不必重新生成整页。
16. 作为一个用户，我想得到能直接双击打开的 `index.html`，而不是一个必须安装依赖才能看的项目。
17. 作为一个用户，我想在交付目录里看到页面、素材、验收截图和简短说明，方便我备份或发给别人。
18. 作为一个 Agent，我想通过状态文件知道当前阶段、上次决定和产物位置，而不是靠重新阅读整段对话猜进度。
19. 作为一个 Agent，我想在决定 ID 或内容版本过期时被拒绝提交，避免旧确认覆盖新方案。
20. 作为一个维护者，我想让方向库、页面蓝图和验收规则可以独立更新，而不改动 CLI 的状态机。
21. 作为一个维护者，我想让 Skill 在没有 OpenChamber 宿主的情况下也能用，这样它是独立项目，不是某个客户端的内部实现。
22. 作为一个维护者，我想让浏览器验收可跳过或失败可解释，不让一个缺失的 Chrome 阻断整个交付。
23. 作为一个维护者，我想让方向库和规则注明来源与许可证，避免把第三方 Skill 整包复制进仓库。
24. 作为一个用户，我想让 SuperWeb 用中文和我交流，但页面文案跟随目标受众的语言。

## Implementation Decisions

### 项目形态

- 独立仓库，建议目录 `/Users/neomei/项目/codexprojects/SuperWeb`。
- 一个 Agent Skill 包，包含 `SKILL.md`、参考文档、方向库、CLI、Schema 和测试。
- v1 不修改 OpenChamber；以后通过“加载 superweb 技能”的创建流程接入。
- 运行时：Node 22+，TypeScript 通过 `tsx` 直接执行，和 SuperPPT 的工程方式一致。
- 依赖保持克制：`zod` 做 Schema，`playwright-core` 只在验收时调用本机 Chrome；不下载 Chromium，不引入前端框架。

### 两条路线

- `page`：浏览型页面，包括落地页、产品页、作品集、活动页、one-pager。
- `app`：工作型界面，包括后台、仪表盘、设置、列表、编辑器。
- 默认从 brief 自动判断，用户可覆盖。两条路线使用不同的区块蓝图和验收规则，共用方向系统、状态机和交付结构。

### 三个阶段门

状态机阶段：

```text
brief -> direction -> sample -> full -> acceptance -> delivered
```

- `direction`：展示 3 个设计方向；同时给出内容结构和每节要证明的内容。用户选定方向并确认结构。
- `sample`：只制作首屏和一个代表区块；`app` 路线制作外壳和一个代表屏幕。必须使用已确认的 token 和真实文案；不生成整页。
- `acceptance`：整页完成并通过浏览器检查后，展示截图、溢出/控制台/资源问题和修复结果。用户接受后进入 `delivered`。

每次 `decide` 都带当前 `stageRevision` 和 `decisionId`。旧版本或旧决定的确认必须被拒绝，不允许静默套用到新方案。

### CLI

CLI 名称：`superweb`。

- `start`：创建任务目录、初始化 `superweb.json` 和 `需求.md`。
- `continue`：返回当前阶段、当前决定、已有产物和下一步。
- `directions`：按 brief 抽 3 个方向并写入 `设计方向.md`。
- `decide`：提交方向、样页或验收决定；校验阶段和 revision。
- `inspect`：启动临时静态服务器，用本机 Chrome 截图并生成 `验收/report.json`。
- `deliver`：检查验收决定和文件完整性，生成交付目录。
- `status`：只读查看状态，不推进阶段。

CLI 不替 Agent 写页面内容；它只拥有状态、决定、验收和交付。

### 状态文件

任务使用 `superweb.json` 作为唯一状态源，至少包含：

```ts
type SuperwebState = {
  version: 1;
  taskId: string;
  route: 'page' | 'app';
  stage: 'brief' | 'direction' | 'sample' | 'full' | 'acceptance' | 'delivered';
  stageRevision: number;
  briefPath: string;
  selectedDirectionId: string | null;
  decisions: Array<{
    id: string;
    gate: 'direction' | 'sample' | 'acceptance';
    revision: number;
    choice: string;
    at: string;
  }>;
  artifacts: {
    brief?: string;
    directions?: string;
    copy?: string;
    sample?: string;
    preview?: string;
    delivery?: string;
  };
  acceptance: {
    passed: boolean;
    reportPath?: string;
    screenshots?: string[];
  };
};
```

任务目录约定：

```text
需求.md
设计方向.md
文案.md
预览/
  v0.html
  index.html
验收/
  desktop.png
  tablet.png
  mobile.png
  report.json
交付/
  index.html
  assets/
  验收/
  说明.md
superweb.json
```

### 方向库

- v1 内置 12 个方向，每次抽 3 个；方向之间必须在“概念、构图、字体、配色、动效、适用场景”上明显不同。
- 每个方向是一份短配方，不把整个网页模板塞给模型。方向库独立于页面蓝图，`page` 和 `app` 可各自选择适用方向。
- 方向来源参考 `ConardLi/garden-skills` 的 `web-design-engineer` 与 `Leonxlnx/taste-skill` 的结构，使用 MIT 许可；不整包复制，README 记录来源与改写范围。

### 页面原则

- 先内容，后版式：每节必须能说出“它在证明什么”，没有作用的区块删除。
- 先设计系统，后写代码：颜色、字体、间距、圆角、阴影和动效在样页前确定。
- 禁止默认 AI 套路：紫粉渐变、Emoji 代替图标、编造数据、假 logo 墙、CSS 画假产品图、无意义的卡片墙。
- 占位符必须明确标记；缺少 logo 或产品图时先询问，不用色块或手绘 SVG 冒充。
- 页面文案用目标受众的语言；Skill 与用户交流默认中文。
- 交互必须有 hover/focus/active/disabled/loading/empty/error 中适用的状态。
- 不新增未要求的区块；内容不足时用构图和版式解决，不靠填充文字。

### 输出与素材

- 默认静态 HTML/CSS/JS；`index.html` 可直接打开。
- React/Vite 只在用户明确要求或页面复杂到需要组件化时使用；这不改变默认验收方式。
- 素材优先级：用户提供的本地素材 > 宿主可用的图片生成能力 > 明确占位符。
- v1 不自动从开放图库抓图，不读取用户浏览器会话，不调用未声明的 API。
- 交付目录必须自包含，图片、字体和脚本路径不得指向用户临时目录。

### 浏览器验收

- 使用 `playwright-core` 启动本机 Chrome；三个视口：桌面 1440×900、平板 768×1024、手机 390×844。
- 至少检查：横向溢出、文字截断、图片加载失败、控制台错误、主按钮可见、键盘可聚焦。
- 截图和 `report.json` 写入 `验收/`；失败项必须出现在用户看到的报告里。
- Chrome 不可用时，`inspect` 返回可解释的失败，用户可选择继续交付但必须明确标注“未完成浏览器验收”。
- 默认在 `acceptance` 阶段运行，不在每次样页修改后运行。

### 修订

- 验收前返工：保留已确认方向，只重做目标区块，阶段回到 `full` 或 `sample` 视修改范围而定。
- 交付后返工：新开 revision，保留上一版 `交付/`，生成 `v2`，不能覆盖用户已拿走的文件。
- 任何方向、内容结构或 token 改变都会推进 `stageRevision`，旧确认失效。

## Testing Decisions

好的测试只验证外部行为：状态转换、决定是否被接受、产物是否存在、报告是否能被用户理解；不把内部函数调用顺序当契约。

- **状态机**：从 `brief` 到 `delivered` 的正常路径；旧 revision 的决定被拒绝；重复提交幂等；跳阶段被拒绝；`page` 和 `app` 路由都能推进。
- **CLI 黑盒**：`start`、`continue`、`decide`、`inspect`、`deliver` 在临时任务目录上运行；断言文件产物和退出码，不读私有模块。
- **方向抽取**：同一 seed 结果稳定；3 个方向不重复；没有足够 brief 时拒绝给出方向。
- **Schema**：缺字段、未知阶段、坏 decision 输入被拒绝；状态文件损坏时不被静默重置。
- **验收**：用手写 fixture 页面模拟横向溢出、坏图片和控制台错误；断言报告列出问题。Chrome 不存在时断言可解释失败。
- **交付**：交付目录自包含；缺验收决定时拒绝交付；旧交付不被覆盖。

测试使用 Node 内置 test runner + `tsx`；浏览器用例在没有 Chrome 时跳过并记录原因。SuperPPT 的 CLI/状态测试结构可作为工程先例，但不复制它的 PPTX 逻辑。

## Out of Scope

- OpenChamber 创建面板、工作台或任何客户端 UI 接入。
- 部署、域名、CDN、表单后端、数据库和真实支付。
- 自动从图库下载图片、自动生成图片、自动读取浏览器登录状态。
- 完整设计系统导入、Figma 导入、多人协作、评论系统。
- React/Vue/Svelte 项目脚手架；v1 只在明确要求时输出可选框架版本。
- 移动端原生 App、视频、PPT 和文档生成。
- 30–45 分钟的完整 taste-skill 精修循环；以后可作为独立“精修模式”。

## Further Notes

- 参考来源：`ConardLi/garden-skills` 的 `web-design-engineer` 与 `Leonxlnx/taste-skill`，两者均为 MIT。SuperWeb 采用其流程结构、方向抽取和反套路原则，不整包复制脚本或文档。
- 第一版目标不是“替代专业设计师”，而是让非技术用户以可理解的节奏做出“不像 AI 默认模板”的网页。
- 进入实现前，需先确认本 spec；实现时先建立状态机和 fixture 测试，再接浏览器验收，最后写方向库和 SKILL.md。
