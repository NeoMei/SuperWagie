Indexed in place; nothing moves

Before indexing, SuperWagie shows how many files there are and which model will be used. The index points at each file where it lives; nothing is copied or uploaded, and deleting the index never touches the originals.

  • New and changed files follow. A save is picked up shortly after; no manual rescan.
  • Deletes are marked first. A file that disappears is marked missing; remove the entry when you are sure.
  • Pause a busy folder. Sync clients and build output can stop indexing without removing the library.

Wiki, graph and gallery

The index is not only for search. Recurring concepts become Wiki pages; the graph connects contracts, reviews and meetings; the gallery browses the images and layouts you indexed.

  • Every node leads back. Wiki and graph are not another silo of notes.
  • Four views, one library. Documents, Wiki, graph and gallery share one index.
  • Failures explain themselves. Unsupported, encrypted or broken files say why on the entry, and can be retried.

The agent reads; it never writes

When a session needs a fact, SuperWagie searches the library first and cites the document and page. It has no write access, so generated content never mixes into source material.

The indexing service starts with the app and listens only on loopback. You never install, configure or open a second product.
