Models & keys

SuperWagie keeps its desktop model configuration in its own app data. When no model is configured, it can use an available free model. Availability and allowances depend on the provider.

Test passed, connection incomplete

A passed embedding test means the new connection can return vectors. Applying it to an existing library index also requires a compatibility check. The original configuration and index remain while that check is pending.

A connection change with the same model and dimensions can preserve existing vectors through a controlled migration after compatibility checks and a backup. Files do not need to be imported again for that migration. Changing the model or dimensions requires assessing migration or regenerating the index. Installing an update does not migrate or rebuild an index automatically.

Auto model selection

Enable Auto in Settings → Routing and choose a fallback from the currently available models. Select the fallback again if its model is removed or its provider changes.

Version 2.7.74 checks model choices before sending. An unavailable fallback prompts you to choose one in Routing settings. If a category model is unavailable, Auto uses the configured fallback and keeps that category's selected agent. It does not substitute a same-name model from another provider. Installing the update retains existing routing settings.

Add your own provider

You can also open Settings → Model providers, add a provider and API key, and choose a default model. A session can switch models individually; new sessions use the default selection.

Where keys and settings live

SuperWagie saves keys in its app data and uses them to authenticate model requests with the selected provider. Installers contain no user keys.

Never paste a key into an issue, a chat or a screenshot. Check logs for credentials before sharing them.

Library models

The library and Experiences tab use the models selected in Model configuration. Configure a connection for each capability you use, such as embedding or document parsing.

Model calls follow the selected provider's billing rules. Connectivity tests, document parsing, and embedding can also call models.

Common errors

Messages follow the current interface language. Expand the details to inspect the response.

  • Model not set up: Use an available free model or add your own provider in Settings.
  • Model connection failed: Check the endpoint, key, and model name in Settings, then run a connection test where available.
  • Free allowance used up: wait for the service to restore the allowance, or choose another configured model.
  • Too many requests: wait a little, then try again.
  • Model unavailable: read the test result and check the key's current model catalog.
  • The desktop engine is not ready: Wait for the desktop engine to start, then refresh.
