Troubleshooting

Start with the log: ~/Library/Logs/SuperWagie/main.log. The last few lines usually name the cause.

The app will not open

  • If 2.7.64 reports that the app is damaged, download 2.7.84 and replace the old copy in Applications. The 2.7.82 repair fixed incomplete bundle signatures; the current build remains unnotarised.
  • Only for a trusted, unmodified package: try opening the app first. If macOS blocks it because it is not notarised, open System Settings → Privacy & Security, scroll down to Open Anyway, then confirm when prompted. See Apple's instructions.
  • Match the installer to your device. The Apple silicon arm64 build requires macOS 13 or later; Windows uses the x64 installer.
  • If Open Anyway is unavailable or the app still will not launch, include the system message in an issue. Attach relevant app logs if any were created.

Startup or session errors

  • agent.list failed (403): update to 2.7.84. Version 2.7.82 fixed the desktop page being rejected by the newer engine's origin check.
  • session.prompt failed (503): requests wait for the engine during startup or restart. If the failure continues, check the log for its cause. A missing session returns 404 separately.
  • Old session not found: SuperWagie uses its private session database and does not import system OpenCode history. Start a new session in SuperWagie; the original database is retained.
  • Key activated but configuration failed: after updating, choose Continue setup under API keys in the account panel. Setup reuses the existing key without another activation.

Model errors

Model messages follow the current interface language. Expand the response details for diagnostic information.

  • Auto reports an unavailable model: open Settings → Routing and select the fallback again from the available models. Version 2.7.82 added the unavailable-fallback check before sending; updating retains existing routing settings.
  • Model not set up: use a bundled free model when no model is configured. To use another model, click your avatar to activate a SuperWagie Key, or add your own provider in Settings.
  • Model connection failed: check the connection settings and key. If your SuperWagie Key is already activated, continue setup in the account panel.
  • Free allowance used up: wait for the service to restore the allowance, or choose another configured model.
  • Too many requests: wait a little, then try again.
  • Timeouts: check the network or try another provider.

Embedding test passed, connection incomplete

The existing index has triggered model-change protection, so the original configuration and index remain. Keep the files and index while checking whether a migration can preserve them. If the model or dimensions change, assess the rebuild scope and cost first. See Models & keys.

Indexing fails

  • Encrypted Office files, broken archives and formats such as RTF cannot be parsed; the entry says why.
  • Files over the size limit are skipped and labelled, so one large file cannot stall the library.
  • Fix the file and retry, or pause the library while you tidy it.

Search returns nothing

  • Check that indexing finished, rather than sitting at “indexing”.
  • Check the scope: all libraries or the current one.
  • Filename and meaning are separate result groups; try another term.

The library service is down

Quit and reopen the app; the service starts with it and listens only on loopback. If it still fails, check whether port 17808 is taken and share the log.

A task file got broken

The workbench lists unparsed lines below the tasks with the line number and reason. Fix the line or restore a backup; nothing is silently deleted.

Memory and conversation learning

The server turns on learning when the library switch goes on. An install upgraded with the library already on gets the setting at first launch. Once learning is enabled, every session with a later conversation in any project enters extraction automatically, including sessions you do not have open. The Experiences tab can pause or resume learning. Sessions from before enablement, and an older open session, remain available through an explicit history import. Failures show a specific reason, and transient failures keep retry available.

  • Enabled but unavailable: the saved setting is retained. Memory reports unavailable until startup succeeds and can retry after the service recovers. If it keeps failing, check the displayed reason and app log.
  • The request does not finish: update to 2.7.84. The Experiences tab shows a specific extraction, persistence or model error, and transient failures can be retried. Resolve model quota or credential problems before retrying.
  • An embedding request fails: update to 2.7.84. Long Chinese content is split at UTF-8 character boundaries, and each embedding request carries one short text. Use Retry indexing for existing failed entries.
  • Learning stayed off after an upgrade: update to 2.7.84 and restart once. The first start migrates an install whose library was already on. Use the Experiences checkbox to pause or resume learning.
  • An older session has no experiences: check whether it happened after the switch was enabled. Sessions from before enablement need an explicit history import.

Windows

Windows x64 uses 2.7.84. The installer is unsigned, so SmartScreen may block the first run. It contains no keys.
